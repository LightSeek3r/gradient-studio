# Internationalisation (web app)

The web app ships English and French with **no runtime dependency**: a typed catalogue per
language, a small `t()` and a provider. PLAN §7: *issue codes are the stable layer*. The core
library keeps English `message` strings and stable `code`s, and the CLI stays English; the app
translates by `code`. Terminology: [`i18n-glossary.md`](i18n-glossary.md).

## Pieces (`apps/web/src/i18n/`)

| File | Role |
|---|---|
| `en.ts` | The source catalogue, one flat object of dotted keys. `MessageKey = keyof typeof en`. |
| `fr.ts` | `Record<keyof typeof en, string>`: a missing or extra key fails `npm run typecheck`. |
| `icu.ts` | ICU-lite formatter: `{name}`, `{n, plural, =0 {…} one {# x} other {# xs}}` (via `Intl.PluralRules`), `{k, select, a {…} other {…}}`, `\{ \}` escapes. Apostrophes are plain text. A malformed message is shown as written, never thrown. |
| `translator.ts` | `createI18n(locale)` gives `t`, `number(n, digits)`, `percent(n)`, `list(items)` (all `Intl`). `tEn` / `i18nEn` are for tests and non-React code. |
| `locale.ts`, `locale-browser.ts` | Locales, detection order, `lang=` parsing (pure) and the `window`/`localStorage` side. |
| `I18nProvider.tsx`, `context.ts` | Active locale, `setLocale`, `useT()`, `useI18n()`. Keeps `<html lang>`, `<title>`, description and `og:`/`twitter:` tags in step (`document-meta.ts`). |
| `LanguageSwitcher.tsx` | EN \| FR radio group in the header (each language named in itself, with a `lang` attribute). |
| `rich.ts` | `renderRich(text, tags)` turns `<code>…</code>` / `<accent>…</accent>` inside one message into nodes. |

Pure modules (`explain`, `import/adapter`, `export/export-model`, `suggest/compare`, `score-band`,
`layout/tabs`) take a `t` (or an `I18n`) argument instead of reading React context, so they stay
testable. Components call `useT()` / `useI18n()`.

## Locale detection

1. `lang=fr|en` in the URL fragment (`docs/URL-FORMAT.md`);
2. the stored choice (`localStorage` key `gradient-studio:lang`, every access in try/catch);
3. `navigator.languages`: the first entry whose primary subtag we have (`fr`, `fr-CA` give French);
4. English.

Choosing a language in the switcher stores it and writes `;lang=` to the address bar. Detected
languages are never written to links.

## What is translated where

- **Rule names and explanations**: `rule.<code>.name` / `.measures`, for every code of scoring
  model v1.
- **Finding messages**: `finding.<code>.<severity>`, one per tier of the model. The UI picks the
  localised text by `code` + `severity`; only an unknown pair falls back to core's English
  `message`. The English entries are word for word core's messages (a test walks `V1_MODEL`).
- **Fix labels**: rebuilt from the fix's `kind`, edited stops and direction of change
  (`explain/fix-label.ts`), not from core's English `label`.
- **Import errors and warnings**: keys under `import.err.*`, `import.warn.*`, `import.reason.*`.
  Core's skip `reason` strings are English phrases; the adapter matches the known ones to keys
  and shows an unknown one as core wrote it.
- **Export notes** from core are matched the same way (`localiseCoreNote`); the code itself is
  never translated.
- **Dates, numbers, lists**: through `Intl` (`0,12` in French; score integers stay digits).

Left English on purpose: code output, CSS keywords and colour names (`indigo`, `to top right`,
`in oklch`), the `rgb(from …)` style samples, brand names (Gradient Studio, GitHub), notation
names HEX/RGB/HSL, channel letters R G B H S L, rule codes (`hue/wide-arc`), the static
`index.html` and `site.webmanifest`, core `message` strings for unknown codes, and the CLI/MCP.

## Add a locale

1. Add the tag to `LOCALES` and `LOCALE_LABELS` in `locale.ts` (short label, native name).
2. Copy `fr.ts` to `<tag>.ts` typed `Record<keyof typeof en, string>`, translate every value, keep
   the placeholders (`{n}`) and tags (`<code>`) identical.
3. Register it in `CATALOGUES` (`translator.ts`).
4. If its plural rules differ, add the branches the language needs (`few`, `many`, …); `other`
   is mandatory.
5. Add a glossary section, then run the checks below. Check every tab at 320, 360 and 1440 px for
   overflow: translations are often 20-30% longer.

## Completeness checks (CI)

- **Typecheck**: the catalogue type makes a missing key a compile error.
- `tests/i18n.test.ts`: same keys and same ICU placeholders per key, markup tags in step, no empty
  value, every message parses, **no identical text unless the key is on a documented technical
  allow-list**, no English function words in French prose, French spacing before `: ; ? !`, no
  verdict words (PLAN D5), every tier of the scoring model and every export note covered, locale
  detection order and `lang=` parsing.
- `tests/i18n-hardcoded.test.ts`: parses every `apps/web/src/**/*.tsx` and fails on JSX text,
  JSX-expression string literals and `aria-label` / `title` / `placeholder` / `label` / … literals
  with letters that are not on the allow-list of technical tokens in that file.
- `tests/i18n-components.test.tsx`: provider, switcher (keyboard, storage failure, `hashchange`),
  and axe on the main components in both locales.
