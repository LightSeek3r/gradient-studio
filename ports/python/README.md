# opal42-gradient (Python port)

A pure-Python port of [Gradient Studio](../../README.md)'s **gradient smoothness
score** (scoring model v1): score a linear gradient 0-100, get coded and located
findings, refine it, build its CSS and sample it. **Standard library only, zero
runtime dependencies**, Python 3.10+, fully typed (`py.typed`).

> **Status: unpublished, working name.** `opal42-gradient` is not on PyPI and no
> name has been reserved there. Publishing is a later step for the project
> owner. Until then, use it from a checkout of this repository.
> The score is a *smoothness score by our definition*, not a validated quality
> verdict ([`docs/PLAN.md`](../../docs/PLAN.md) D5).

## Privacy and scope

This package performs **no I/O of any kind**: no network access, no file or
environment access, no clock, no randomness, no telemetry, no analytics, no
crash reporting. Every function is a pure function of its arguments, results are
immutable dataclasses, and there is no global mutable state. Scoring a gradient
never leaves the process that calls it (see [`PRIVACY.md`](../../PRIVACY.md) and
[`SCOPE.md`](../../SCOPE.md)).

**It implements the frozen v1 model and nothing else.** The TypeScript package
in `packages/core` is the reference; the golden vectors in `spec/vectors/` are
the contract. Ported: colour conversions (sRGB, linear, OKLab, OKLCH), hex / rgb
/ hsl / name parsing and formatting, `score_gradient`, `suggest_gradient` /
`refine_gradient`, `build_gradient_css`, `build_multi_gradient_style`,
`interpolate_gradient`, `color_at_position`, `complement_hex`.
**Not ported:** the CSS gradient *parser* (`parseGradient`, `spec/parser.md`),
the document API (`score(doc)`, `toCSS`, `bakeStops`, `proposeFixes`) and the
exporters (`@opal42/gradient/export`). Those need a separate port. Details and
the conformance results: [`docs/python.md`](../../docs/python.md).

## Use

```python
from opal42_gradient import Stop, score_gradient, suggest_gradient, build_gradient_css

stops = [Stop("#ff0000", 0), Stop("#0000ff", 100)]   # or ("#ff0000", 0) / {"color": ..., "position": ...}

result = score_gradient(stops)
result.score                # 87
result.details              # lightness 30, hue 22, chroma 15, spacing 20 (+ measurements)
for f in result.findings:   # coded, located, same codes and messages as the TypeScript engine
    print(f.code, f.points_lost, f.stops, f.segment, f.message)

better = suggest_gradient(stops)                 # never scores lower; keeps hard and achromatic stops
build_gradient_css(better, 90)                   # 'linear-gradient(90deg, #ff006c 0%, #5c00e7 100%)'
```

Positions are percentages 0-100 (the reference engine's unit). Input outside the
v1 domain (fewer than two stops, anything but `#rrggbb`, positions outside 0-100)
gives `status == "unscorable"` with a `reason` and never raises.

## Test and check conformance

No installation and no network are needed:

```sh
cd ports/python
python3 -m unittest discover -v          # unit, property and conformance tests (pytest also works)
python3 scripts/check_conformance.py     # summary of the vector run; exit status 1 on any mismatch
python3 scripts/gen_names.py --check     # the 148-name table is generated from the TypeScript source
```

The suite replays the **same** `spec/vectors/v1-*.json` files as the TypeScript
tests: exact equality on every non-boundary case (hex and CSS strings, integer
scores, finding codes and locations, messages), measurements within a tight
tolerance on boundary-flagged cases, and it prints the counts.

| `src/opal42_gradient/scoring_model.py` | `V1_MODEL`, measurements, boundary table (frozen dataclasses) |
